Case Study 1 — Azure Healthcare Claims Lakehouse

Business problem

A healthcare analytics team receives daily medical and pharmacy claims from multiple partners. Files arrive in inconsistent CSV layouts, contain duplicates and malformed dates, and must be standardized for downstream quality and utilization reporting.

Architecture

Partner SFTP / API → Azure Data Factory → ADLS Gen2 (Bronze) → Azure Databricks (PySpark) → Delta Lake (Silver/Gold) → Synapse serverless SQL / Power BI

Supporting services:

  • Key Vault for secrets; Managed Identity for service-to-service authentication.
  • Azure Monitor + Log Analytics for pipeline and job telemetry.
  • Purview for catalog, lineage, and classification.
  • Private Endpoints, RBAC, storage firewalls, and encryption for security.

Data zones

  • Bronze: immutable source files, ingestion timestamp, source filename, batch ID.
  • Silver: standardized types, normalized codes, deduplication, rejected-row quarantine.
  • Gold: member-month, provider utilization, paid-claims summaries, quality measures.

Processing steps

  1. ADF schedules ingestion and lands source files in date-partitioned ADLS paths.
  2. ADF records file name, size, checksum, arrival time, and run ID in an audit table.
  3. Databricks reads Bronze with an explicit schema; avoid schema inference for production feeds.
  4. Validate required fields, allowed claim status, non-negative paid amount, and date ranges.
  5. Deduplicate by claim business key and latest source update timestamp.
  6. Write valid rows to Silver Delta tables using an idempotent merge/upsert pattern.
  7. Aggregate Gold tables for reporting; optimize partitioning based on query patterns.
  8. Publish pipeline status, row counts, rejects, and freshness SLA.

Example validation rules

  • claim_id and member_id must be present.
  • service_date must parse and not be unreasonably in the future.
  • paid_amount >= 0.
  • A repeated claim key should resolve to the latest source_updated_at.
  • Rejected rows retain a reason code and source lineage.

Reliability and scale

  • Make ingestion idempotent using source file identity + batch ID.
  • Use retries for transient storage/network failures, not for deterministic data errors.
  • Separate technical failures from data-quality failures.
  • Use Auto Loader or a controlled incremental file discovery pattern for high-volume landing.
  • Use Delta MERGE for late-arriving corrections.
  • Reprocess a date or batch from Bronze without asking the source to resend.

Security

Use managed identities instead of embedded credentials; store any unavoidable secrets in Key Vault. Apply least-privilege RBAC and table-level access. Mask or tokenize direct identifiers in analytical layers. Use private networking and audit access to sensitive datasets.

Interview walkthrough

Question: How would you handle duplicate and late-arriving claims? I would preserve every raw delivery in Bronze, identify the claim business key, and compare source update timestamps. Silver would use a deterministic merge so reruns do not create duplicates. Late corrections update the existing claim while retaining ingestion and source lineage. I would monitor duplicate rates and late-arrival lag.

Question: How do you troubleshoot a failed ADF pipeline? Start with the pipeline and activity run IDs, inspect the failing activity and integration runtime, classify the error, validate source availability and permissions, and check the Databricks job logs. Retry only transient errors. After correction, rerun the affected batch using the same batch identifier and confirm row counts and audit status.

Portfolio implementation

Run python src/transform_claims.py. It reads data/healthcare_claims.csv, standardizes fields, deduplicates claims, and writes:

  • output/claims_silver.csv
  • output/claims_rejected.csv
  • output/claims_gold_daily.csv

The included code is a local demonstration of the transformation logic. For Azure deployment, replace local reads/writes with ADLS paths and execute the transformations as a Databricks job orchestrated by ADF.
