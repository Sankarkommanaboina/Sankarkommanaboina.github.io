Case Study 3 — GCP Mobility Streaming Analytics

Business problem

A mobility company receives trip events from vehicles and mobile clients. Operations teams need recent trip volume, duration, distance, and service-area trends, while analysts need historical reporting.

Architecture

Mobile / vehicle producers → Pub/Sub → Dataflow (Apache Beam) → BigQuery raw + curated datasets → Looker

Supporting services:

  • Cloud Storage for replay/archive and batch backfills.
  • Cloud Composer for scheduled dependencies and backfills.
  • Cloud Monitoring and Cloud Logging for operational visibility.
  • IAM, Secret Manager, CMEK where required, and VPC Service Controls for governance.

Streaming design

  1. Producers publish versioned trip events to Pub/Sub.
  2. Pub/Sub subscriptions decouple producers and stream processors.
  3. Dataflow validates schema, parses event time, enriches service-area metadata, and handles late events with event-time windows and allowed lateness.
  4. Valid events are written to BigQuery; invalid events go to a dead-letter topic or quarantine table.
  5. BigQuery SQL builds hourly and daily aggregates.
  6. Looker dashboards expose operational and historical trends.

Important concepts

  • Event time vs processing time: use event timestamps for business windows so delayed messages do not distort reporting.
  • Windowing: tumbling hourly windows are suitable for hourly operational metrics; session windows may suit user activity.
  • Late data: define allowed lateness and update aggregates when late events arrive.
  • Exactly-once expectations: understand connector guarantees and design downstream writes for deduplication using event IDs.
  • BigQuery cost: partition by event date, cluster by common filter keys, and select only required columns.

Data quality

Validate event ID, trip ID, event timestamp, positive duration, non-negative distance, and recognized service-area code. Monitor null rates, duplicate IDs, late-event percentage, and event-to-dashboard latency.

Interview walkthrough

Question: How would you handle late-arriving events? I would use event-time processing in Dataflow, define a watermark and allowed lateness, and configure the aggregation strategy to accept late updates. I would preserve raw events so historical windows can be recomputed if a correction exceeds the lateness threshold.

Question: How do you control BigQuery cost? Partition tables on the event date, cluster on frequently filtered dimensions, avoid SELECT *, set query cost controls, and materialize repeated expensive transformations when justified.

Portfolio implementation

Run python src/transform_mobility.py. It validates and deduplicates synthetic trip events and creates daily area-level metrics.

For a GCP deployment, provision Pub/Sub topics and subscriptions, deploy a Dataflow streaming template or Beam pipeline, and create partitioned BigQuery tables. Use service accounts with narrowly scoped roles.
